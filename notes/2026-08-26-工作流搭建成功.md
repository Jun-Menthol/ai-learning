## 🛠️ 工作流设计

### 整体架构

用户输入 → 开始节点 → 搜索节点（头条搜索） → 大模型节点 → 结束节点 → 输出计划

### 各节点配置

| 节点 | 类型 | 核心配置 |
| :--- | :--- | :--- |
| **开始** | 起始节点 | 输入变量 `input`，供后续节点引用 |
| **搜索** | 插件节点 | 使用「头条搜索」插件，`input_query` 引用 `开始.input` |
| **大模型** | 模型节点 | 模型：豆包·2.0·pro，提示词要求基于搜索结果生成计划 |
| **结束** | 输出节点 | 输出引用 `大模型.output` |

## 🔧 关键问题与解决

| 问题 | 原因 | 解决方案 |
| :--- | :--- | :--- |
| `Jinja2 Syntax err` | 变量引用格式错误（中文节点名、手动输入变量） | 使用编辑器 `{}` 按钮插入变量，确保节点名称一致 |
| `变量值不可为空` | 搜索节点的 `input_query` 未正确接收用户输入 | 通过 `{}` 按钮正确引用 `开始.input` |
| 大模型输出通用计划 | 搜索结果未传递给大模型 | 在系统提示词中正确引用 `搜索.data` |

### 核心经验
1. **节点名称以画布显示为准**：引用变量时，节点名必须与画布上一致（如 `开始` 就是 `开始`，不是 `start`）。
2. **使用 `{}` 按钮插入变量**：避免手动输入 `{{}}` 导致的语法错误。
3. **搜索节点的输出变量名**：通常为 `data`，需要先确认再引用。

## 💡 学习心得

1. **工作流的本质是“编排”**：把多个能力（搜索、生成）按顺序组合，解决复杂问题。
2. **数据流是核心**：工作流的关键不是节点本身，而是节点之间数据的传递路径。
3. **调试是必经之路**：每次报错都在帮助你更深入地理解系统规则。
4. **提示词是“人机接口”**：清晰的指令决定了输出的质量上限。
